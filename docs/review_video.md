# 振り返り用の編集動画と振り返りプレーヤー

ナイスミルの処理結果（参加者ごとの行動記録・根拠の時刻・人物の枠・生成した文）を使って、
元の試合動画から「振り返り用」の動画を作ります。映像を生成AIで作り替えることはしません。
切り出し・字幕・枠・目印を、ふつうの動画編集（PyAV / OpenCV）で重ねるだけです。
映像はこのサーバー（パソコン）の中だけで扱い、外には出しません。

> 公開版の注意：姿勢・ボール検出・動作の確認の手がかり（`--pose-file`、`--ball`、`--claim-cues` の入力ファイル）を作る道具は、
> AGPL-3.0 の ultralytics に依存するため、このリポジトリには含めていません。これらの引数は任意で、ファイルが無くても動きます
> （その機能が無効になり、画面や標準エラーにその旨が出ます）。

## 作るもの

1. **ハイライト編集動画**（参加者ごとに1本、`NN_<名前>.mp4`、1280x720・H.264・無音）
   - 文章が根拠にした場面（なければ、よかった場面すべて）を、前4秒・後3秒つきで切り出して連結
   - 重なる場面は1つの続きの場面にまとめ、文は場面の時刻に合わせて切り替わる
   - 画面: 青い枠と名前（対象の人だけ。審判・控え・観客など、ほかの人には既定で枠を付けない。
     コマンドに `--others` を付けたときだけ、ほかの人に灰色の細い枠）、上に「動画の時刻」と
     「AIの判定・要確認」、下の帯に「試合時間 …・種類」「AIの記録（生成された文）」
     「評価のポイント（生成された文）」「AIの下書きです。評価する人が確認してから渡します。」
   - 人物の一致の予備判定（名前の段階の背番号の読み取りが、その時刻に別の番号を示す場面）が
     あるときだけ、その場面はオレンジの枠と「別の人かも」の表示、帯にも注意の1行。判定の材料が
     ない場面には何も出さない
   - 先頭に説明のカード、最後に注意と出典（CC BY などのクレジット）のカード
   - 文は生成されたまま。3行に収まらない長い文だけ末尾が「…」になる（プレーヤーでは全文）
2. **振り返りプレーヤー**（`player/review_player.html` と動画の2つ。外部CDN・通信なし）
   - 左に動画と枠。既定で出る枠は「選んだ人の枠」だけ。ほかの人の灰色の枠は「全員の枠」を
     入れたときだけ出る（審判・控え・観客まで枠が付いて試合が見づらくなるため）。時間軸に場面の目印、再生速度、前/次の場面
   - 映像の上の小さな字幕（再生バーの上、字は12〜16px）は、既定で「選んだ人のコメントだけ」。枠と字幕が同じ人を指す（外すと全員ぶん。C キーで字幕の入/切）
   - 右に参加者ごとの「よかった所」の一覧。クリックで、その場面の4秒前へ移動（ハイライト動画と同じ、前4秒・後3秒の窓）
   - 再生位置に合わせて、いまの場面の行が強調され、下にその文が出る
   - キー: 空白=再生/停止、←→=5秒、N/P=次/前の場面
   - 下書きの人には「下書き」と出る。「確認が済んだ」とは出さない

## 作り方（コマンド）

```
cd <このリポジトリ>
PYTHONPATH=src .venv/bin/python -m pfb_app.review_video SUBMISSION_ID \
    --settings PATH/settings.yaml --out OUTDIR \
    [--subject SUBJECT_ID ...] [--credit "出典の行"] [--no-player] \
    [--claim-cues CUES.json] [--ball BALL.json] [--others]
```

- `SUBMISSION_ID`: ナイスミルの解析の番号（作業の中の、動画の組ごとの番号）。`--settings`: ナイスミルの設定ファイル（`data_dir` が入ったもの）。
- `--claim-cues`: 動作の確認（姿勢の手がかり。外部の姿勢測定ツールで作る）。付けると、手がかりと合わない動作の文を断定しない形に直す。
  **付けないと、「よかった所」の文はAIの記録のまま**（その旨を画面の注意と標準エラーに出す）。
- `--ball`: ボール検出（外部のボール検出ツール）の結果。ボール保持の赤い丸（推定）を出す。`--others`: ハイライト動画で、ほかの人にも灰色の細い枠。
- 引数が間違っているとき（解析の番号・設定ファイル・`--claim-cues`/`--ball` のファイルが無い、`--out` がファイル）は、理由を1行で標準エラーに出し、
  **何も書かずに**終了コード2で終わる。`--subject` の人がいないときはその旨を `notes` に出し、何も作らなければコード1。
- 出力先に前回の動画が残っているときは、上書きも削除もせず、`notes` に「前回までの動画が残っています」と出す（同じ名前のものだけ作り直す）。

`OUTDIR`（権限 0700）に `NN_<名前>.mp4`（0600）と `player/`（動画は元ファイルの **コピー**、ハードリンクではない。0600）ができます。アプリのデータの中には書きません。保存期間・削除の対象外なので、不要になったら `OUTDIR` ごと消してください。
データベースは **読み取り専用**（SQLite `mode=ro`、`PRAGMA query_only`）で開きます。WALへの切り替え、`init_schema`、ALTERは実行しません（書こうとすると例外）。Python からは `pfb_app.review_video.service.make_all` /
`make_person_video`、データだけ欲しいときは `collect.build_package`。

## 運用中のサーバーへ入れる手順の案

- **段階A（コードの配置だけ。画面は変わらない）**: レビューしたうえで運用中の版に取り込み、
  配備の手順（バックアップ → 更新 → 起動確認）で入れる。データベースの変更はない（CLIは読み取り専用で開くので、運用中のDBを書き換えない）。
  取り込み後は、サーバーで `cd ~/pfb_app && env -u VIRTUAL_ENV ~/.local/bin/uv run python -m pfb_app.review_video ...`
  で作れる（出力先はアプリのデータの外）。
- **段階B（画面のボタン）**: 「文章を確認する」画面と詳細画面の「解説動画」の隣に
  「振り返り用の編集動画を作る」「振り返りプレーヤーを作る」を足す。作るのは時間がかかる
  （実測: 60秒の動画・10人で約100秒、3分の動画・15人で約195秒）ので、`services/explainer.py` と同じ型の worker ジョブ
  （依頼 → 進み具合 → 完成ファイル + 作ったときの状態の印）にする。置き場所は
  `<group>/handout/explainer/highlight_<id>.mp4` と `.../review_player/`（保存期間・削除・
  データ消去は既存の `handout` フォルダの扱いにそのまま乗る）。ジョブの種類の追加が
  `explainer_jobs` の制約に当たるか（スキーマ変更が要るか）は、実装時に確かめる。
  ボタンの文言は中立（評価する人・参加者）にし、`tests/test_neutral_wording.py` の対象に加える。

## 色・吹き出し・選手以外・ボール・見どころ機能（2026-11-18）

- **色はチームごと**（個人別ではない）: チームA = 青、チームB = ピンク、判定なし = 濃いグレー。服の色から推定した
  2つの群で、チーム名・実際のユニフォームの色ではない（凡例にもそう書く）。アプリ自身の T1/T2 の判定があればそれを優先。
  枠・札・吹き出しの縁と番号チップ・人物ボタン・タイムライン・ハイライト mp4 の枠が同じ色。赤＝ボール保持専用、黄＝コート外周専用、
  「要確認」は色でなく ▲ の記号と点線の枠。3色の区別は、通常・色覚の3型（シミュレーション）で Lab 色差 20 以上（テストで検査）。
  個人は、吹き出し・札の背番号/ID表記と、選んだ人の太い枠で見分ける。
- **頭上の吹き出し**: よかった所の窓（前4秒・後3秒）に入った人のコメントを、その人の枠の頭上に出す（しっぽが頭を指す、
  枠に追従、1〜2行、同時最大2人（5回目の点検で3→2）・1人1つ、端でクランプ、重なりは上へずらす、枠が見えない時は下端の字幕に退避）。
  先頭の番号チップは「3番？」「番号不明（P10）」のまま（背番号ゲートが閉じている間は断定しない）。
- **選手以外（審判・コーチ）の推定** `nonplayer.py`: 追跡ごとの胴体色（Lab、色の強い画素の中央値）を平均連結の群に分け、
  大きい2群をチームとし、そこから外れる小さな色の群を「選手以外」とする。スコア＝0.6×(チーム群からの色の遠さ)＋0.4×(群の小ささ)。
  0.65以上は「選手以外（推定）」として既定で人物一覧・場面・吹き出し・ハイライト動画から外す（「選手以外も表示」で見られ、
  「選手に戻す」で戻せる）。0.4以上は「選手以外かも」の印だけ。チーム色が付いた人（アプリの判定）には絶対に付けない。
  人数が5人未満なら判定しない。使っていない手がかり: コート上の位置・滞在の仕方（デモに登録が無いので使っていない）。
- **ボール保持の赤い丸（推定）**: 外部のボール検出ツール（YOLO11 の sports ball、1280px）の結果 JSON を `--ball` で渡すと、
  `holder.py` が「ボールが信頼度0.4以上で映り、1人の枠にだけ明確に近い」フレームを保持者とし、前後3フレームを足し、
  6フレームまでの欠損をつなぐ。ボールが見えない時間は丸を出さない。プレーヤー・ハイライト動画に、足元の赤い楕円。
  JSON が無ければ機能自体が出ない。場面の文との矛盾の検査はしていない。
- **コート外周**: アプリにコート登録（geometry）がある映像でだけ、その四隅を黄色の線で描く（推定はしない）。
  デモ（Samsunspor）には登録がないので出ない。カメラが動く映像で、静止した線は引かない。
- **見どころ機能**（すべてスイッチ、すべて既定オフ（実況メモも、5回目の点検で既定オフにした））: 実況メモ（画面内の人数をチーム群別に数え、いま記録されている場面と
  ボール保持の推定を並べるだけ。データが無ければ「この時刻の人物の記録がありません」。順位づけ・比較はしない）、前/次の見せ場、見せ場だけ連続再生、
  見せ場は0.5倍速、スポットライト、足跡（直近3秒）、画面を保存、ショートカット一覧（?）。
  ミニコート（俯瞰図）は、コート登録のデータが無いと作れないため未実装。

## 限界

- 動画はカメラ1台ずつ。プレーヤーは場面の多いカメラ1台ぶんだけ（ほかは件数を表示）。
- 追跡が別の人に移った場面は、予備判定（背番号の読み取り）が効く場合にしか分からない。
  オレンジの表示がないことは「別人ではない」という意味ではない。
- 時刻のない場面は入れない（件数を notes に出す）。
- 文章が下書きのままでも作れる（下書きと明記）。承認済みの文に限る設定にはしていない。
- 縦長の動画は左右に余白ができる。4K/HEVC の動画は、再生用の変換（proxy）が終わるまで作れない。

## 追加（11/17 夕）: イベントのタイムラインと背番号表示

### タイムライン（プレーヤー、動画の直下）
- 横軸は全編の長さ。参加者ごとに1行。行動の記録（◯）、よかった所（◆、文の根拠は縁取り太め）、
  人物が別人かもしれない所（▲オレンジ）を、時刻の位置に印で出す。**形と色の両方で区別**する。
- 印にカーソル／フォーカス／タップで、人・時刻・したこと・よかった所の文（生成文のまま）を小さく表示。
  クリックでその4秒前から再生（動画と同じ前4秒・後3秒）。再生位置の縦線が動く。行ごとのチェックで出し入れ、「全員を出す/消す」、
  ＋－全体（Ctrl+ホイールも）で拡大縮小。
- キー: ←→ = 前/次のイベント（出ている行の全部）、Shift+←→ = 5秒、N/P = 選んだ人の前/次のよかった所、空白 = 再生/停止。
- 人どうしを比べる表示（件数・順位）は出さない。人の並びは チーム→背番号→ID の中立な順。
- ハイライト動画にも、全編の細いタイムライン（映像の下、選んだ人だけの印と再生位置）を入れた。

### 背番号表示（動画・プレーヤー・タイムライン）
- 表示名 = 背番号（`3番`、チームが分かれば `Aチーム 3番`。胴体色の名前は決められないので A/B）。
- 背番号は **アプリが人の名前づけに使っているものと同じ**（`services.auto_people._read_number`:
  名前の段階の読み取りで、異なるフレームで `MIN_FRAMES_AGREE`（2）以上一致、または番号の時系列で全体の半分以上着ている番号）。
  推測はしない。一致しない・読めない人は `番号不明（P2）`（追跡IDは内部IDとして残す）。
- 注意: `configs/cue_gate.yaml` の精度ゲートでは、背番号の手がかりは今のところ **無効**（保持分 6/7=0.857、
  n=7 < 20、要求は 0.90 以上かつ n≥20）。アプリの「#3」の名前づけも暫定のもの。だから画面に
  「背番号はAIが読んだもの。違っていたら直してください。」を必ず出す。資料にある数値はこの 0.857 と
  チームの被覆率 0.18（< 0.50）だけ（運用メモの「番号一致 0.84〜0.89、チーム 24/24」は未照合）。
- 同じ番号が別チームにあるときはチームで区別。同じチーム（またはチーム不明）で同じ番号が2人 → 両方に
  `番号が重複・要確認`。1人の追跡が別々の番号を読んでいる → `番号不明` + `番号が食い違う・要確認`。
- 追跡の途中で読み取った番号が変わる所（番号の時系列で隣り合う区間の番号が違う）は、タイムラインに ▲ で
  `人物が別人かも・要確認`。番号の時系列がなければ印は出ない。
- 字幕の文は生成文のまま。表示ラベルは別の枠（上の帯、枠のタグ）で、文には手を入れない。
  「ナイスミル上の名前」と追跡IDは小さく補助表示。
- 直す入口: 既存の「人物と参加者の対応づけ」（`ui/pages/review.py` の MAPPING_TAB）と
  `auto_people.rename_person`（評価する人の名前は番号名づけが上書きしない）。画面の注意書きでそこを案内している。
  番号そのものを直す専用の入力欄は無い（案: 人物シートに「背番号を直す」欄を足し、`name_source` を coach にする）。
- アプリ全体への展開案: 人物の表示名を 番号優先（`3番`/`Aチーム 3番`）にし、`番号不明（P2）` を既定にする。
  既存の「選手n」「#n」の名前づけと衝突するので、段階B（ボタン）より後、別リリースで。


## 点検の指摘への対応（11/17 夜）
- 背番号は **精度ゲートを通っていない間は常に「3番？」** と出し、枠は点線、固定の注意
  「背番号の読み取りは、精度の基準に届いていません（試験で7人中6人。基準は0.90以上・20人以上）」と
  「背番号はAIの読み取りで、精度は未検証です」を、導入・終了カード、帯、プレーヤー上部・下部に出す。
  ゲートが開いているかは、名前の段階の実行結果の `gate.number.enabled`（全カメラ）で決まり、開いているときだけ
  断定表示（「3番」、実線の枠、ゲートの注意なし）に切り替わる。
- 「オレンジの印が無くても、別の人でないとは限りません」を常時表示。人物ごとに「人物の照合：番号の時系列で
  確かめました／材料がなく、確かめていません」を出す。
- 絞り込み（`--subject`）の前に、全員で背番号の重複・食い違いを判定する。重複・食い違いのときは、枠のタグ・
  行名に追跡IDを併記する（「Aチーム 7番？（P3）」）。
- 種類での絞り込み（よかった所・行動の記録・要確認）。よかった所が「別人かも」のときは、◆の形と根拠の縁を
  保ったままオレンジにする。前後の窓は動画とプレーヤーで同じ（前4秒・後3秒）。

## 見やすさの作り直し（2026-11-17）

「文字が多くてどこを見ればいいのかわからない」への対応。機能は変えず、見せ方だけを直した。

- 読む順番は「大きな映像 → すぐ下のタイムライン → 「いまの場面」カード1枚」。
- 常時表示していた注意（背番号は精度未検証、印が無くても別人でないとは限らない、AIの下書き、直す手順、保存方針、出典）は、細い上帯「AIの下書き・背番号は未検証 ⓘ」に集約。ⓘ で開くパネルに、同じ文をそのまま移した（内容は削っていない）。画面に常時出る人物の警告は、タイムラインの▲とカードの1行だけ。
- カードは「だれ（背番号？）・時刻・よかった所の文（生成文そのまま、20px）」だけ。「したこと・根拠・名前・人物の照合」は「くわしく」の奥。
- 人物はチップ（「8番？」「14番？（P6）」）で選ぶ。右側の一覧は初期は閉じる。「全員を見る」で全行表示。
- 種類フィルタ・拡大縮小・速さ・枠は映像の下の1行のツールバーに集約。
- 初回だけ吹き出し3つ（① ここで再生 ② ここで場面を選ぶ ③ ここに文が出る）。×で閉じると localStorage（使えない環境では毎回）で二度と出さない。
- 文字は最小14px。色は白・深緑・要確認のオレンジのみ。◆●▲、キーボード操作は維持。
- 動画の帯は「だれ・時刻・よかった所の文」と1行の注意（「AIの下書き・背番号は未検証」／確認済みなら「AIの下書き・要確認」）だけ。詳しい注意は前後のカードに残る。点線枠・「？」・別人かもの橙はそのまま。

## 再生中のリアルタイムコメント（2026-11-17）

## 全員の評価文とチーム別の表示（2026-11-18）

**見つけたこと**: デモ（15人）で評価文が出ていたのは3人だけだった。理由は2つ。(1) アプリの評価文（pfb段階）は、人ごとに1つの段落で、
「貢献あり」と判定された場面が無い人（6人）には作られない（根拠不足）。(2) 動作の確認で弱めた場面が1つでもある人は、その段落が弱めた動作を
言い直している恐れがあるため、プレーヤーは全文を出さない（`text_withheld`）。シュートの場面はほぼ全員で弱められるので、結果として3人になった。

**変えたこと**:
- `evalgen.py`: アプリ自身の評価文の段階（`pipeline.video.run_pfb`、同じ指示文・同じ検査）を、ローカルのモデルで、人ごとに1回ずつ動かす。ただし材料は
  「動作の確認を通り、人物の取り違えの印も無い場面」（`claims.eligible`）だけ。弱めた場面と、シュートと読める文（「放った」を含む）は材料にしない。
  データベースは**コピー**（`--work-dir`）の中で、通らなかった場面の判定を「貢献なし」にして動かす。ライブのDBにも、読み取り専用で開いたDBにも書かない。
  根拠不足の人には、アプリが元から持つ事実だけの短い文（`services.short_text.compose`）を付け、「短い文」と明示する。事実は作らない。
- `claims.guard_text`: 出来た文をもう一度検査する。確かめた場面に無い動作を言う文、確かめたシュートが無いのにシュートを言う文、場面に無い結果（得点など）を言う文は
  「〜ているように見える（要確認）」にする。人どうしの比較に読める文は外す。背番号は数字のあと必ず「？」。
- プレーヤー: 人物ボタンを「チームA／チームB／チーム不明」にまとめ（見出しはチームの色。服の色からAIが分けた組で、チーム名ではない）、
  選んだ人の評価文を見える場所に出す。組の順は固定、組の中は ID 順。得点・評価の順や、チームどうし・人どうしを比べる並べ方はしない。選手以外（推定）の人は、評価文を作らない。
- 使い方: `python -m pfb_app.review_video.evalgen SUBMISSION_ID --settings S.yaml --out texts.json --work-dir DIR --claim-cues CUES.json`、
  そのあと `python -m pfb_app.review_video SUBMISSION_ID ... --claim-cues CUES.json --eval-texts texts.json`。モデルは、この機械の上のものだけ（クラウドは使わない）。
- `pipeline/claim_check.py`: シュートの語に「放った・放つ」を加えた（「ボールを放った」は、シュートと同じ動作の主張として確かめる）。

**残っていること**: 評価文は下書きで、動作を映像で確かめたものではない（確かめられる動作はシュートの腕の高さだけ）。評価する人が映像で確かめる。

## 全員の枠・服の色・常時の吹き出し・赤いコート枠（2026-11-18、仕様変更）

要件「全員に枠をつけて、チームの服の色（白は白・赤は赤）で表す。常に頭上に吹き出しで今やっていること・背番号を出す。コートの枠を赤い線で囲う」に合わせ、
これまでの仕様（チームA青／チームB桃、吹き出しは2件まで・場面のときだけ、コート枠は黄色、赤はボール保持専用）を次のように変えた。
**この節が現在の仕様**（上の節の「赤＝ボール専用」「黄＝コート」「吹き出し2件まで」「既定は選んだ人の枠だけ」は古い）。

### 見つけた問題 → 変更 → 作り方 → 結果
1. **全員に枠**
   - 問題: 追跡に載らない人は、既定で枠が出ず、「全員の枠」でも薄い灰色だった。画面上の選手のうち、既定で枠があったのは約4割。
   - 変更: 追跡が名前を付けなかった人（extras）と、リストにない追跡（P11など）も、**服の色で決めたチームの色の枠**にする。既定で全員の枠が出る
     （スイッチ「全員の枠」。ボタンの外観は初期チェック）。審判などの選手以外（どちらの服の色でもない）は、これまでどおり既定で枠なし（「選手以外も表示」で灰色の点線）。
   - 作り方（`everyone.py`）: 映像を1回通して、全部の枠の上半身（幅の中央50%、高さ18〜52%）の色の中央値を取る。チームの色＝そのチームのリスト済みの人の中央値。
     extras・リスト外の追跡は、短い追跡（`link_rows`、近い枠をつなぐ）ごとに、いちばん近い服の色（Lab距離。しきい値18）へ投票してチームを決める。どちらにも近くない色は選手以外。
     体の姿勢ファイル（外部の姿勢測定ツール、ローカルのYOLO姿勢）があるときは、追跡にもextrasにも無い人の枠（ポーズ検出）も、
     「選手たちの足の範囲の中にいる」「服の色がどちらかのチーム」「0.5秒以上続く」ときだけ、選手として足す。
2. **服の色の枠**
   - 変更: A/Bの青／桃をやめ、**映像から推定した服の色**（上半身の中央値）を枠の色にする。白→白、黒→黒（背景に溶けないよう、太さと反対色の縁取り:
     白い枠には黒、黒い枠には白）。色の名前（白・黒・赤・青…）は測った色から付け、凡例とボタンの見出しに「白のチーム」のように出す。
     2チームの色が似て見分けにくいとき（Lab距離38未満または同じ名前）は、2チーム目を見分けやすい色（赤は使わない）に寄せ、**凡例に「寄せています」と書く**。
   - 限界: 映像の明るさで白い服が灰色に写る（デモは測った色が灰色で、「白」の判定を明度0.48以上にした）。色の名前は推定で、クラブの名前ではない。
3. **常時の吹き出し**
   - 変更: すべての枠の頭上に、背番号（「N番？」、読めなければ「番号不明」）と「いまの様子」を**全時刻**で出す。場面のコメント（最大2件）は従来どおり。
     場面のコメントが出ている人は、その吹き出し（確認済みの場面の文）を優先し、常時の吹き出しは重ねない。
   - 「いまの様子」（`everyone.activity`）: ボール保持（ボールの検出があるときだけ）＞腕を上げている（手首が頭より上、姿勢ファイルがあるとき）＞しゃがんでいる＞
     走っている／歩いている／立っている（足元の速さ。体の高さ／秒で 0.35・1.25 が境。カメラの動きは連続フレームの位相相関で引く）。0.5秒ほどでならして、ちらつかせない。
     言葉は全て「〜ように見える」か「（推定）」。シュート・パス・得点などの動作は、確認した場面（◆、claim_check）の外では出さない（テストで固定）。人や組を比べる文は無い。
   - 配置: canvasに描く（DOMを増やさない）。近い人（枠が大きい人）から置き、重なったら上へ、横へずらす。それでも置けなければ番号だけに縮め、それでも置けなければ吹き出しを省く
     （枠は必ず出る）。スイッチ「全員の吹き出し」。選んだ人は太い枠と名札で強調。
4. **赤いコート枠**
   - 調べたこと: デモの解析データにはコート登録が無い。登録があるときは、これまでの4隅を**赤い線**（黒い縁）で描く（黄色をやめた）。ボール保持者の印は、赤＋白縁に
     薄い赤の塗りを足した楕円（形が違う）。
   - 推定（`court_est.py`、映像だけ）: 床の木の色と、その外側の濃い青の縁取りの境目を、列ごとに集め、RANSACで直線に当てる。奥側の辺は「縁取りの外に床が無い・縁取りが薄い」、
     手前側の辺は「縁取りの外に床が無い」を条件にする。さらに**選手たちの足の位置が、線の内側にある（9割）**ことを確かめ、合わない線（ゴール下の塗装の縁・ロゴ）は捨てる。
     0.5秒ごとに推定し、画面では前後のサンプルのあいだを補う（1.5秒より離れていれば出さない）。出た線には「コートの枠（推定）」の札を付ける。
     推定が25%未満の時間にしか出なければ、線は一切出さない。
   - 限界: 出るのは**見えている範囲の長い辺（主に奥側のサイドライン）**だけ。手前側の辺・短い辺・隅は、映像に映らない／見分けにくいため、ほとんど描けていない（嘘の四角は描かない）。
     縁取りの色が床と違わない会場、強い反射の場面では出ない。

### 使い方・追加の引数
- 姿勢ファイル: サーバーなど GPU のある機械で 外部の姿勢測定ツール（動画 → pose.json） →
  `python -m pfb_app.review_video N --out DIR --pose-file pose.json`。無くても動く（「腕を上げている／しゃがんでいる」だけ出ず、追跡の増やし方も弱くなる）。
- `--no-court-estimate`: 映像からのコート推定をしない（登録のあるときだけ線が出る）。
- ハイライトmp4（`edit.py`）の枠・黄色のコート線は、今回は変えていない（プレーヤーだけの変更）。

## コートの外周で囲う・外にいる人は控え・観客かも（2026-11-19、設計）

設計方針「コート枠を線で囲い、外にいる人は控え選手や観客かもしれないとして扱う」の試作。審判はコートの中にいるので、外周の内外では審判は除けない
（審判は従来どおり服の色・同色の小さな組で扱う）。外周の外は、控え・観客・ベンチの人のための追加の手がかり。

### 見つけた問題 → 変更 → 作り方 → 結果
1. **四隅の登録**
   - 問題: 推定の線（`court_est.py`）は奥側のサイドラインだけ（73%）で、四角形で囲えていない。カメラはパン・ズームする。
   - 変更: 人が画面を見てコートの外周の四隅を1回登録し（`docs/court_reg/*.json`、根拠の線を書く）、カメラの動きは機械が追跡して四隅を動かす（`court_reg.py`、`--court-reg FILE`）。
   - 作り方: 放送カメラは1点から振るので、どの2枚も平面の射影変換（ホモグラフィ）で結べる。0.5秒おきの画面の特徴点（SIFT）を隣どうしで対応づけ、RANSACで変換を求め、
     以前の画面（キー画面）にも直接つないで誤差をためない。全画面を基準の1枚に貼り合わせた画像（モザイク）の上で四隅を読み、時刻ごとに逆変換する。
     対応が弱い・変換が極端・カメラが切り替わった時刻は線を出さない。四隅が画面の外にあっても、辺は直線なので見える部分だけが正しく出る。
   - 結果: デモ（公開クリップ Samsunspor TBF、180秒）で360時刻すべてで追跡でき、18時点の画面で外周が合っていることを確かめた。
2. **コート外の判定**（`court_reg.flag_rows`）: 足元（枠の下辺の中央）を、四隅を28x15mの長方形とみなした平面に写し、外周の外へ1m以上（登録のずれと線を踏む動きの余裕）、
   1秒以上続いたときだけ「コート外」。一度でも2秒以上コートの中にいた追跡は、外に出ても選手のまま（スローイン等）。足元が画面の下端に切れた枠・外周が分からない時刻は判定しない。
   名前を付けた（評価する）人は、外周の外でも枠を消さない。外にいる人は既定で枠なし、「選手以外も表示」で灰色の点線と「コート外かも」。判定は行ごとに出し、1秒未満の出入りは立てないので点滅しない。
3. **3段階との関係**: コート外は「中」（選手以外かもの印）にあたる。単独では除外（高）にしない。服の色の外れ値などと重なっても、除外の判断は従来の手がかりのまま。
